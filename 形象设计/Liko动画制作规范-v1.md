# Liko 动画制作规范 v1

> 适用对象：角色视觉、动效设计、Rive/SVG 制作、H5 前端、后端。  
> 适用版本：深圳大学校园 AI 伴生助手 H5 第一版。  
> 本规范用于统一角色结构、身份数据、五种状态动画和交付验收口径。

## 1. 已确认的核心设定

1. Liko 是“柔软的内层角色穿着完整荔枝外壳”的双层结构，不是直接给一颗荔枝加五官。
2. 所有用户的角色轮廓、比例、五官位置、外壳结构、叶片与果梗结构一致。
3. 外壳颜色和内层肤色分别从各自色板中随机抽取；两者互不推导，也不由编号决定。
4. 角色生成后，外壳颜色和肤色永久落库。刷新、换设备、切换状态时不得重新随机。
5. 每位用户只能拥有一个 Liko。公开编号仅按用户注册顺序生成，例如 `No. 000001`。
6. 不设置随机徽章、发卡、挂件或其他个体配饰。学习、听歌、健身、游戏所需物品只是状态道具，不属于用户身份装饰。
7. 第一版只有五种状态：待机、学习、听歌、健身、打游戏。

视觉基准文件：

- `Liko正式设定/Liko-标准三视图与配色-v1.png`
- `Liko正式设定/Liko-五状态关键姿势-v1.png`

如基准图与本规范发生冲突，以本规范中的“固定结构”和“身份规则”为准，并由产品负责人确认后再改稿。

## 2. 角色固定结构

### 2.1 外层荔枝壳

- 外壳必须形成完整、连续、能包裹内层角色的荔枝轮廓。
- 正面保留一个连续的大开口，用于露出内层脸部和身体；开口边缘要体现“壳套在身体外面”的前后遮挡关系。
- 外轮廓可以使用圆润、轻微起伏的荔枝表面，不应画成花瓣、狮子鬃毛或可拆卸披风。
- 果梗与叶片是外壳固有结构，位置和形状固定，不参与用户随机。
- 外壳可以随呼吸产生极轻微的整体弹性，但不可像液体一样大幅变形，也不能与内层身体穿插。

### 2.2 内层角色

- 内层为柔软、圆润、简洁的小生物本体，包括身体、脸、双手和双脚。
- 身体、手、脚必须使用同一个肤色变量；任何状态下都不得出现手脚与身体颜色不一致。
- 五官结构固定：两只眼睛、一个简洁嘴型；可以因状态改变表情，但不可更换五官风格。
- 身体始终位于外壳内部，只有脸部、手、脚按照动作需要从开口或底部露出。

### 2.3 固定与可变边界

| 项目 | 是否因用户变化 | 是否因状态变化 | 说明 |
|---|---:|---:|---|
| 角色轮廓与比例 | 否 | 仅允许轻微形变 | 所有用户一致 |
| 外壳颜色 | 是 | 否 | 注册时随机一次并落库 |
| 内层肤色 | 是 | 否 | 注册时独立随机一次并落库 |
| 果梗、叶片颜色 | 否 | 否 | 使用统一品牌色 |
| 五官样式 | 否 | 表情可变 | 位置和线条风格固定 |
| 编号 | 是 | 否 | 仅由注册顺序决定 |
| 书、耳机、哑铃、手柄 | 否 | 是 | 只在对应状态出现 |
| 徽章、发卡、挂件 | 不使用 | 不使用 | 第一版禁止加入 |

## 3. 画布、尺寸与安全区

- 主画板名称：`liko_main`。
- 标准坐标系：`512 × 512`，SVG 使用 `viewBox="0 0 512 512"`，背景透明。
- 角色常态视觉中心：`(256, 250)`；脚底基线建议位于 `y=410` 附近。
- 角色本体及状态道具须保留至少 32 px 四周安全区，音乐音符等短暂特效也不得越界裁切。
- 主体在移动端的建议显示宽度为 220–320 CSS px；缩至 160 px 时，五官、双层关系和主要道具仍需可辨识。
- 编号不写死在动画文件中。动画只提供 `serial_anchor` 定位锚点，H5 使用可访问的文本层渲染实际编号。

## 4. SVG / Rive 分层与命名

所有图层、节点、骨骼和动画统一使用小写 `snake_case` 英文命名。发布后不得随意改名，以免前端绑定失效。

### 4.2 遮挡规则

- `shell_back` 在内层身体后方，`shell_front` 和开口边缘在身体前方，以形成真实的“穿壳”关系。
- 手臂可以根据动作拆为前后两段，但手持道具时，手掌必须在道具正确一侧，避免漂浮或穿透。
- 双脚从外壳底部露出；脚与身体使用同一肤色变量。
- 状态道具离开对应状态后必须完全隐藏，不得残留透明像素、碰撞区域或占位空白。

### 4.3 Rive 命名

- Artboard：`liko_main`
- State Machine：`sm_liko`
- 动画：
  - `idle_loop`
  - `study_loop`
  - `music_loop`
  - `fitness_loop`
  - `gaming_loop`
  - `transition_in`
  - `transition_out`
- State Machine 输入：
  - `mode`：Number，`0=idle`、`1=study`、`2=music`、`3=fitness`、`4=gaming`
  - `is_active`：Boolean，组件是否处于可见且活动状态
  - `reduce_motion`：Boolean，是否启用减少动态效果
- 颜色数据绑定：`shell_color`、`skin_color`。若使用的 Rive 运行时不支持直接绑定颜色，使用同名绘制对象由前端在初始化阶段赋色；不得为每种颜色复制整套动画。

### 4.4 SVG 命名与颜色变量

SVG 根元素需要支持以下 CSS 变量：

```css
--liko-shell-color: #e85b62;
--liko-skin-color: #fff0bd;
--liko-face-color: #443d3c;
--liko-leaf-color: #89bd55;
--liko-stem-color: #a86f42;
```

- 外壳基础填色只能引用 `--liko-shell-color`。
- 身体、手和脚只能引用 `--liko-skin-color`。
- 高光使用低透明度白色叠层，阴影使用低透明度深色叠层，避免前端为每个基础色计算多组衍生颜色。
- 编号文字由 H5 DOM 覆盖层渲染，SVG 内只保留锚点，不嵌入字体和固定编号。

## 5. 随机配色与落库规则

### 5.1 配色色板

第一版建议从经过视觉确认的有限色板中抽取，不直接生成任意 RGB，以避免脏色、荧光色或外壳与肤色难以区分。

**外壳色板 v1**

| Key | 色值 | 说明 |
|---|---|---|
| `lychee_red` | `#E85B62` | 荔枝红 |
| `coral` | `#F47B72` | 珊瑚橙红 |
| `berry_pink` | `#EE86A8` | 莓果粉 |
| `grape` | `#A78BDA` | 葡萄紫 |
| `ocean_blue` | `#6C9FEA` | 海湾蓝 |
| `mint_teal` | `#4AB9A9` | 薄荷青 |

**内层肤色色板 v1**

| Key | 色值 | 说明 |
|---|---|---|
| `cream` | `#FFF0BD` | 奶油黄 |
| `peach_milk` | `#FFD9C2` | 桃子奶 |
| `mint_milk` | `#DFF3D8` | 薄荷奶 |
| `sky_milk` | `#DBEEFF` | 天空奶蓝 |
| `lavender_milk` | `#EEE2FF` | 薰衣草奶紫 |
| `rose_milk` | `#FFE3EC` | 玫瑰奶粉 |

正式色值仍需在三种屏幕亮度下完成视觉校色后冻结。色板更新必须增加 `palette_version`，不得直接修改已有 Key 对应的历史颜色。

### 5.2 生成逻辑

1. 后端在首次成功创建角色时，从外壳色板随机抽取一个 `shell_color_key`。
2. 后端再从肤色色板独立随机抽取一个 `skin_color_key`。
3. 两次抽取不读取编号，也不以用户 ID、手机号、学号或编号作为颜色种子。
4. 抽取后做最低可读性检查：内层肤色与五官必须清晰，外壳开口与内层边界必须可辨识。不合格只重抽颜色，不改变编号。
5. 颜色与角色记录在同一个创建流程内持久化。接口重试时先查询现有角色，不得重复抽色。

建议保存字段：

```text
user_id             用户唯一标识，唯一约束
public_serial       注册顺序号，唯一约束
shell_color_key     外壳色 Key
shell_color_hex     创建时实际色值快照
skin_color_key      肤色 Key
skin_color_hex      创建时实际色值快照
palette_version     色板版本，初始为 1
created_at          创建时间
```

前端只负责显示后端返回的数据，不在浏览器端重新随机颜色。

## 6. 编号规则

- 展示格式：`No. 000001`，`No.` 后保留一个空格，数字部分至少六位，不足左侧补零。
- 数据库存储原始整数，例如存储 `135`，展示层格式化为 `No. 000135`。
- `public_serial` 仅由数据库顺序或受事务保护的发号逻辑产生，前端不得自增或猜测下一个编号。
- 编号按照角色首次成功创建的先后顺序分配；并发注册时以数据库实际发号顺序为准。
- 编号一经分配永久不变，不因改名、换颜色、注销、重新登录或切换设备改变。
- 已使用编号不回收、不补发给其他用户；允许因为事务回滚或账号删除产生空号。
- 编号与外壳颜色、肤色、人格和五种状态没有任何计算关系。
- 每个 `user_id` 只能关联一个 `public_serial`，数据库同时设置两项唯一约束。
- 编号文本不参与角色骨骼动画，不缩放抖动；切换状态时保持位置稳定。

接口返回示例：

```json
{
  "publicSerial": 135,
  "publicCode": "No. 000135",
  "appearance": {
    "shellColorKey": "berry_pink",
    "shellColor": "#EE86A8",
    "skinColorKey": "mint_milk",
    "skinColor": "#DFF3D8",
    "paletteVersion": 1
  }
}
```

## 7. 五状态动画规格

通用要求：

- 五种状态共享同一套角色骨骼和绘制结构，不复制五个不同角色。
- 所有循环首尾姿势、位置、缩放和透明度必须一致，逐帧检查不得跳变。
- 呼吸形变以整体缩放和轻微位移为主，推荐幅度不超过原尺寸的 2%。
- 身体弹性遵循“先身体、后外壳与叶片轻微跟随”的节奏；禁止高频果冻抖动。
- 状态道具使用固定设计和固定颜色，不随用户随机配色。
- 下表时长为目标值，成片允许在 ±10% 范围内微调，但须保持节奏自然。

### 7.1 待机 `idle`

- 循环时长：4.0 秒，无限循环。
- 道具：无。
- 表情：放松、轻微微笑。
- 关键帧：
  - `0%`：标准站姿，重心居中。
  - `20%`：身体吸气上浮约 2–3 px，外壳轻微撑起。
  - `42%`：回落至中位，叶片延迟轻摆。
  - `48%–53%`：完成一次快速眨眼。
  - `72%`：重心向一侧移动约 2 px，手部轻微跟随。
  - `100%`：完全回到首帧。
- 可选微动作：将眨眼拆为独立子动画，在 4–7 秒范围内触发一次；随机只影响触发时机，不改变角色外观。

### 7.2 学习 `study`

- 入场：0.30 秒；循环时长：4.8 秒；无限循环，离开状态后退出。
- 道具：`prop_book`；允许最多一个低频灵感闪光 `fx_study_spark`。
- 表情：专注、眼睛看向书页。
- 关键帧：
  - `0%`：书本已稳定打开，双手正确托住两侧。
  - `18%`：头部轻微下压，视线移动到左页。
  - `34%`：右侧书页抬起，右手跟随。
  - `45%`：书页翻到左侧，纸张不得穿过脸或外壳。
  - `55%`：书页落稳，双手回到托书姿势。
  - `72%`：轻微点头或眨眼，闪光淡入淡出一次。
  - `100%`：回到首帧姿势。
- 禁止：耳机、键盘、长期漂浮文字、连续高亮闪烁。

### 7.3 听歌 `music`

- 入场：0.32 秒；循环时长：3.2 秒；无限循环，离开状态后退出。
- 道具：`prop_headphones`、`fx_music_notes`。
- 耳机佩戴：头梁跨过外壳顶部；左右耳罩分别贴合角色两侧对应位置，尺寸和高度基本对称；禁止单边悬空、耳罩戴在脸上或头梁穿过果梗。
- 表情：开心、放松，可在重拍处稍微加深笑容。
- 关键帧：
  - `0%`：重心居中，音符隐藏或低透明度。
  - `25%`：身体向左摆 3–4°，右侧叶片延迟跟随；一个音符上浮。
  - `50%`：经过中位并轻微下沉，耳罩仅做很小的呼吸缩放。
  - `75%`：身体向右摆 3–4°；另一音符上浮。
  - `100%`：回到首帧，音符完成淡出。
- 音符同屏最多 3 个，只使用位移、缩放和透明度，不做密集粒子效果。

### 7.4 健身 `fitness`

- 入场：0.28 秒；循环时长：3.6 秒；无限循环，离开状态后退出。
- 道具：`prop_dumbbell_l`、`prop_dumbbell_r`；允许一个汗滴 `fx_sweat`。
- 表情：认真但不痛苦，动作结束时可露出小得意。
- 关键帧：
  - `0%`：双手持哑铃位于身体两侧，膝部微屈。
  - `18%`：下蹲至最低点，外壳整体下移但不压扁内层脸部。
  - `38%`：起身并将哑铃抬至肩部，手掌与哑铃保持绑定。
  - `55%`：达到最高点并停留 2–3 帧，出现一个汗滴。
  - `76%`：哑铃缓慢落回身体两侧。
  - `100%`：恢复首帧。
- 动作节奏要体现轻量健身，不表现剧烈喘息、摔倒或过度拉伸。

### 7.5 打游戏 `gaming`

- 入场：0.30 秒；循环时长：3.0 秒；无限循环，离开状态后退出。
- 道具：`prop_controller`、`fx_game_feedback`。
- 表情：投入、轻微兴奋，视线朝向手柄上方的虚拟屏幕方向。
- 关键帧：
  - `0%`：双手握住手柄，手柄位于身体正前方。
  - `20%`：左手轻推摇杆，身体向左微倾。
  - `40%`：右手按键，按钮做一次 90–120 ms 缩放反馈。
  - `58%`：表情短暂惊喜，出现一次像素星光或胜利闪光。
  - `78%`：身体向右微倾并回稳。
  - `100%`：回到首帧，特效完全淡出。
- 禁止：屏幕大面积闪烁、快速震屏、控制器与手掌分离。

## 8. 状态切换规则

1. 首次加载从五状态随机队列中取第一项；动画资源加载失败时才回退到静态 `idle`。角色颜色和编号数据准备完成前可显示统一骨架占位，不得先随机一套颜色再跳到真实颜色。
2. 前端通过 `mode` 切换状态；同一时刻只能激活一种主状态。
3. 正常切换使用 250–350 ms 的缓入缓出。先收回旧状态道具，再建立新姿势并淡入新道具。
4. 外壳色、肤色和编号在状态切换过程中保持不变，禁止颜色渐变或重新随机。
5. 连续快速切换时采用 350 ms 防抖，只执行最后一次有效状态；不要把多个入场动画排队播放。
6. 切换到 `idle` 时，状态道具应在前 40% 的过渡时间内隐藏，然后回到标准站姿。
7. 页面不可见、角色滚出屏幕或组件销毁时，设置 `is_active=false` 并暂停时间轴；恢复可见后从当前状态平滑继续，不补播离屏期间的帧。
8. 状态由产品界面决定，动画文件不自行根据时间永久修改状态。若临时动作结束需要回待机，由前端业务逻辑明确设置 `mode=0`。
9. 产品界面不提供手动状态选择按钮；当前状态只作角色生活表现，不作为用户可修改的属性。
10. 主状态每 60 分钟由业务层自动切换一次，页面刷新或短暂离线不能触发重新抽取。
11. 五种状态采用“洗牌袋”顺序：一轮内每种状态只出现一次，全部出现后再洗牌进入下一轮；新一轮第一项不得与上一轮最后一项相同。
12. H5 原型可在浏览器本地保存队列、当前状态和上次切换时间；正式版应按用户保存在后端，以保证多设备一致并防止清缓存后重抽。

## 9. H5 接入约定

- 角色组件接收的最低参数：`mode`、`shellColor`、`skinColor`、`publicCode`、`reduceMotion`。
- 颜色值和编号必须来自登录用户的后端角色接口，并缓存到当前用户状态；不得从 URL 或本地随机值作为最终身份数据。
- 编号使用普通文本元素放置在 `serial_anchor` 对应位置，并提供可读文本；不要把编号转成无法被辅助技术读取的图片。
- 加载失败时显示静态待机图和真实编号，不显示其他用户缓存过的颜色与身份数据。
- SVG 方案优先通过 `transform` 和 `opacity` 动画；Rive 方案只保持一个活动实例，列表页缩略角色使用静态图。
- 分享卡片或导出图片需要编号时，由独立渲染流程写入真实编号，不修改源动画文件。

## 10. 移动端性能标准

- 目标：主流手机稳定接近 60 fps；低端 Android 可降至 30 fps，但不得明显卡顿或阻塞问答输入。
- 单个角色动画资源目标：Rive 文件不超过 500 KB；SVG/CSS 动画资源压缩后不超过 250 KB。超过目标需说明原因并由前端评估。
- 建议 SVG 节点不超过 150 个、路径不超过 120 条，同时运动图层不超过 20 个。
- 优先使用位移、旋转、缩放和透明度；避免动画化路径形状、滤镜参数、阴影模糊和大面积遮罩。
- 禁止持续使用 SVG 高斯模糊、复杂混合模式、视频纹理或高密度粒子。
- Canvas/Rive 渲染分辨率的设备像素比建议上限为 2；更高像素比不应重复增加渲染负担。
- 角色离开可视区域时用 `IntersectionObserver` 暂停；标签页进入后台时用 Page Visibility API 暂停。
- 首屏先显示轻量静态待机图，动画运行时按需加载；动画资源加载失败不得影响 AI 问答主体功能。
- 验收机型至少覆盖：360 px 宽低端 Android、390 px 宽 iPhone、常见微信内置浏览器和系统浏览器。

## 11. 减少动态效果与无障碍

- 默认读取系统 `prefers-reduced-motion: reduce`；若产品提供应用内开关，用户选择优先于系统默认并持久化。
- `reduce_motion=true` 时：
  - 不播放无限循环、弹跳、摇摆、音符上浮、汗滴和像素闪光。
  - 切换状态直接显示该状态的静态关键姿势，或使用不超过 100 ms 的淡入淡出。
  - 状态道具仍然显示，不能因停动画而丢失“学习/听歌/健身/游戏”的语义。
- SVG/CSS 必须提供 `@media (prefers-reduced-motion: reduce)` 停止规则；Rive 必须接入 `reduce_motion` 输入。
- 角色是装饰时使用空 `alt` 或从辅助技术中隐藏；角色承担当前状态信息时，由外层组件提供中文可读标签，例如“Liko 正在学习”。
- 编号文本保持足够对比度和最小 12 CSS px 字号，不随角色呼吸缩放。

## 12. 交付物

视觉/动效最终交付应包含：

1. `liko_main.riv`：含一个主画板、一个状态机和五种状态动画。
2. `liko_main.svg`：标准静态待机版本，保留规定图层 ID 和 CSS 颜色变量。
3. 五种状态的透明背景静态 PNG，至少提供 1× 和 2×，用于降级与分享场景。
4. 色板表：颜色 Key、HEX、色板版本及校色确认记录。
5. 预览页：可切换五种状态、两种颜色、减少动态模式和暂停/恢复。
6. 动画交付说明：Rive 版本、Artboard、State Machine、输入参数和状态编号。

## 13. 验收清单

### 13.1 形象与结构

- [ ] 能一眼看出“外层荔枝壳包住内层角色”，不是荔枝直接长脸，也不是花瓣外套。
- [ ] 外壳开口的前后遮挡正确，动作全过程无明显穿帮。
- [ ] 身体、双手和双脚始终使用同一个肤色。
- [ ] 果梗、叶片、五官位置和角色比例在五种状态中一致。
- [ ] 未加入徽章、发卡、挂件或其他随机配饰。

### 13.2 身份数据

- [ ] 首次注册分别随机得到外壳色和肤色，刷新、重新登录和换设备后保持不变。
- [ ] 颜色随机与编号、用户 ID 和状态无计算关系。
- [ ] 同一用户重复请求创建角色时，不产生第二个角色、不重新抽色、不重新发号。
- [ ] 编号按 `No. 000001` 格式展示，注册后永久不变且不回收。
- [ ] 多用户并发注册时编号唯一，数据库约束能够阻止重复。

### 13.3 五状态

- [ ] 待机、学习、听歌、健身、打游戏均能从同一角色结构正确播放。
- [ ] 五个循环首尾无跳帧，使用 0.5 倍速逐帧检查通过。
- [ ] 学习状态的书页不穿过脸、外壳或双手。
- [ ] 听歌状态头梁和左右耳罩位置正确，耳机不悬空、不穿过果梗。
- [ ] 健身状态双手与哑铃保持绑定，身体不过度压扁。
- [ ] 游戏状态双手正确握住控制器，按键反馈不造成高频闪烁。
- [ ] 离开状态后对应道具与特效完全消失。

### 13.4 切换与前端

- [ ] 五种 `mode` 数值映射与本规范一致，Rive/SVG 图层命名一致。
- [ ] 频繁切换状态时不堆积动画、不闪色、不残留道具。
- [ ] 页面进入后台或角色滚出屏幕后动画暂停，恢复时不突跳。
- [ ] 动画加载失败时静态待机图、真实配色和真实编号仍可显示。
- [ ] 编号由 H5 文本层渲染并可被辅助技术读取。

### 13.5 性能与无障碍

- [ ] 目标机型长时间播放无明显掉帧、发热异常或输入卡顿。
- [ ] 资源体积、节点数和同时运动图层数量达到第 10 节目标。
- [ ] 系统开启“减少动态效果”后停止循环，只显示清晰的静态状态姿势。
- [ ] 暂停动画不影响 AI 问答、页面滚动、输入框和按钮响应。
- [ ] 360 px 宽屏幕下角色、道具和编号无裁切或重叠。
