# Liko 问答 API 接入说明

当前页面已经接入自有后端的 SSE 接口契约。未配置 FastGPT 时，后端返回联调占位且不会把示例内容作为答案；配置完整后，后端会代理 FastGPT 的真实流式问答。

## 安全边界

- H5 不能直接保存或调用 DeepSeek API Key。
- 正确链路是：`手机 H5 → 自有 FastAPI → 自托管 FastGPT → 模型服务`。
- FastGPT 应用 Key 只保存在 FastAPI 的后端环境变量 `FASTGPT_API_KEY`；模型服务 Key 只保存在 FastGPT 部署环境中。两者都不得写进 HTML、JavaScript、`VITE_*`、浏览器缓存或日志。
- 开发、测试和生产使用不同 Key；已经公开发送过的 Key 应撤销后重新生成。

## 第一版建议

- 联调模型：`deepseek-v4-flash`。
- 向量模型：`bge-m3`。
- 默认关闭思考模式，校园常规问答优先追求速度和成本。
- 单次回答建议限制在约 500–800 个输出 token。
- 前端只提交 `conversationId`、`requestId` 和用户问题，不允许前端指定模型、系统提示词或输出上限。
- 后端负责拼接角色提示、历史对话与以后接入的 RAG 检索结果。
- 流式响应只向前端发送 `meta`、`delta`、`sources`、`done`、`error` 等业务事件。

## 当前 SSE 契约

`POST /api/chat/stream` 请求体：

```json
{
  "requestId": "web_...",
  "conversationId": null,
  "message": "校园卡丢了怎么补办？",
  "campus": "粤海",
  "source": "input"
}
```

响应的 `Content-Type` 为 `text/event-stream`：

- `meta`：`requestId`、`conversationId`、`answerId` 和当前运行模式。
- `delta`：增量文本，字段为 `text`。
- `sources`：官方来源数组；无可靠来源时必须为空数组。
- `done`：结束原因与是否允许反馈。
- `error`：可展示的业务错误；不得包含密钥、上游请求头或内部堆栈。

未配置上游时以 `integration_stub` 结束，`canRate` 为 `false`。真实答案成功生成并获得稳定 `answerId` 后才允许提交反馈。FastGPT 的 `flowResponses.quoteList` 会在后端转换为来源；只有 `https://szu.edu.cn` 及其 HTTPS 子域名能够作为校园官方来源返回 H5。

## 开发期保护

- 每个用户同一时间最多一个生成请求。
- 设置每分钟、每天的请求上限和总预算开关。
- 输入限制长度，防止重复点击，超时后允许取消或重试。
- 不默认记录用户完整问题，不在日志中输出 Key 或上游请求头。
- AI 服务不可用时，页面仍应正常显示两页 UI 和已有内容。

## 高频问题与回答反馈

- `GET /api/recommendations` 返回最多 4 条问题卡片；当前实现按近 7 天时间衰减、独立用户数和来源类型排序，并在动态样本不足时用固定常用校园问题补齐。
- 用户主动输入的问题与推荐问题点击必须区分记录，推荐点击不能直接累加为自然热度，避免“越推荐越热门”。
- 相似问法先聚合为同一个问题主题，再按照近 7 天独立用户数、时间衰减、答案满意率和来源有效期计算推荐顺序。
- 只推送已有可靠答案、仍有有效来源的问题；校园事务、生活服务、学习资源应保留基本多样性。
- 每条回答使用稳定的 `answerId`。好评/差评记录 `rating`，差评可附带“不准确、已过期、没回答问题、表达不清、来源有问题”等原因。
- 同一用户对同一回答只保留一条反馈，允许修改或撤销；匿名标识由服务端生成，不保存学号。
- 好评/差评用于回答排序、RAG 问题定位和人工核查队列，不直接自动改写事实，也不直接作为训练数据。
- “不准确”或“已过期”必须结合对应引用、知识库版本和官方资料核查后再更新。

## 游客、登录与长期记忆

- 游客无需登录即可正常问答，但只保留当前会话上下文，每日默认 10 次，不能建立长期人格与偏好记忆。
- 第一版使用账号密码，不要求手机号或邮箱。注册后默认每日 50 次，并按注册顺序生成唯一编号和持久化双层配色。
- 登录会话使用 30 天 HttpOnly Cookie；忘记密码使用注册时只展示一次的恢复码，不把密码、会话令牌或恢复码写入 localStorage。
- 登录用户可开启或关闭“让 Liko 更了解我”。只有开启后，后端才会查询和更新 Mem0 长期记忆。
- 登录身份必须来自服务端会话。前端不得提交一个任意 `userId` 来访问或写入记忆。
- 用户可以通过“Liko 对我的了解”查看、修改、删除单条记忆或清空全部记忆。
- 健康、家庭、财务等内容不按类别自动禁止记忆；开启长期记忆时需要清晰说明可能保存这些内容，并提供关闭与删除能力。
- Mem0 记忆不能作为校园事实来源。后端只把与当前问题相关的少量用户记忆放入 FastGPT 的 `memory_context` 变量，学校政策、日期、费用和地点仍必须来自官方知识库引用。
- 姓名和“我在实习/在某公司实习”等明确个人近况由后端即时写入当前账号的 Mem0 空间；“我叫什么名字”“我最近在干嘛”这类确定性问题直接读取该账号记忆并返回空来源，不调用校园知识库。

## 登录用户对话记录

- 每次聊天沿用服务端返回的 `conversationId`；登录用户的消息与来源会按账号保存，游客仍只保留当前页面会话。
- `GET /api/users/me/conversations` 列出自己的对话，`GET /api/users/me/conversations/{conversationId}/messages` 读取消息，`DELETE /api/users/me/conversations/{conversationId}` 删除整次对话。
- 所有记录接口必须从 HttpOnly 会话识别用户并在服务端检查归属，不能接受前端自报的 `userId`。

## 文件与图片附件

- H5 先用 `multipart/form-data` 调用 `POST /api/chat/attachments`，得到短期附件 ID；随后把最多 3 个 ID 放入聊天请求的 `attachmentIds`。不能把模型密钥或用户 ID 放进上传请求。
- 文档在自有后端解析为文字；超过前端阈值的手机大图先缩放压缩，再由单独的视觉模型限长提取文字与客观描述，作为本轮参考资料进入 FastGPT。当前文本模型不直接接收图片。
- 单个附件默认最大 10 MB。原始文件只在请求内存中处理，不落盘；提取结果默认 24 小时过期，发送成功后前端调用删除接口提前清理。
- 对话记录只保存附件名称和类型，不保存附件正文。长期记忆也只处理用户当前问题和回答，不自动把整份附件写入 Mem0。
- 用户附件不是深圳大学官方来源。若回答依赖附件必须明确说明，校园政策仍应以 FastGPT 返回的深大官方 HTTPS 来源为准。
- 只有明确的校园事实问题展示知识库来源；陪伴聊天、个人记忆和普通附件问答即使上游检索到校园知识块，也必须向 H5 返回空来源。
- FastGPT OpenAPI 自身不接收二进制文件，只接受已上传后的 URL；Liko 当前在自有后端先完成解析，因此不需要公开附件 URL。[FastGPT 文件输入说明](https://doc.fastgpt.io/zh-CN/docs/introduction/guide/course/fileInput)、[FastGPT 对话接口](https://doc.fastgpt.io/zh-CN/openapi/chat)。

## Liko 配色

- 游客不生成正式编号，页面每次打开时在完整 sRGB 色域随机外壳色和肤色，并避开难以分辨的组合。
- 注册成功会生成随机初始配色，并赠送一次自选机会；用户可稍后再选，只有确认颜色时才消耗机会。
- `PATCH /api/auth/liko-colors` 接受 `{ "shell": "#RRGGBB", "skin": "#RRGGBB" }`。后端必须校验登录身份、颜色格式、可辨识度和剩余机会，不能只依赖前端按钮状态。
- 首次机会确认后，颜色永久写入账号并跨设备同步；未来再次换色由道具系统重新授权，不允许通过重复登录绕过。

模型名称和价格会调整，正式接入前以 DeepSeek 官方模型与价格页面为准：

- <https://api-docs.deepseek.com/quick_start/pricing/>
- <https://api-docs.deepseek.com/guides/thinking_mode>
